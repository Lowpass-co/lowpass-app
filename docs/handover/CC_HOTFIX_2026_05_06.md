## 2. Phase 1 — Move `resolveBudgetTab` out of the client-only file (~20 min)

**Symptom:** `/budget/[tourId]` server-renders, hits `resolveBudgetTab(sp.tab)` at `page.tsx:71`, server throws:

```
Error: Attempted to call resolveBudgetTab() from the server but resolveBudgetTab is on the client.
It's not possible to invoke a client function from the server, it can only be rendered as a
Component or passed to props of a Client Component.
  at .next/server/app/(app)/budget/[tourId]/page.js (digest: 2655211188)
```

**Root cause:** `src/components/budget/BudgetTabNav.tsx` line 12 is `'use client'`. It exports:
- The `BudgetTabNav` React component (correctly client-side — uses `useSearchParams`).
- The `BudgetTab` TypeScript type.
- `resolveBudgetTab(raw)` — a pure function that's nothing but a switch statement.

Next 16 strict server/client boundary rejects server-side import of a client-marked function. The fix is a one-file split.

### 2.1 Fix

Create `src/components/budget/budget-tab-utils.ts` (NO `'use client'` directive):

```ts
/* ============================================
   LOWPASS — Budget · tab utilities (server-safe)

   Pure helpers extracted from BudgetTabNav.tsx so the per-tour
   server page can resolve the active tab without crossing the
   server→client boundary (which Next 16 rejects).
   ============================================ */

export type BudgetTab =
  | 'summary'
  | 'budget'
  | 'actuals'
  | 'reports'
  | 'settings';

export function resolveBudgetTab(
  raw: string | string[] | undefined,
): BudgetTab {
  const candidate = Array.isArray(raw) ? raw[0] : raw;
  switch (candidate) {
    case 'budget':
    case 'actuals':
    case 'reports':
    case 'settings':
      return candidate;
    default:
      return 'summary';
  }
}
```

Update `src/components/budget/BudgetTabNav.tsx`:
- Remove the local `BudgetTab` type export and `resolveBudgetTab` function.
- Re-export them from the new module so existing client-side imports keep working:

```ts
'use client';

import Link from 'next/link';
import { usePathname, useSearchParams } from 'next/navigation';
import { cn } from '@/lib/utils';
import {
  type BudgetTab,
  resolveBudgetTab,
} from './budget-tab-utils';

// Re-export for backward compat with existing imports.
export { type BudgetTab, resolveBudgetTab };

const TABS: ReadonlyArray<{ id: BudgetTab; label: string }> = [
  // ... (unchanged)
];

export function BudgetTabNav(/* unchanged */) { /* ... */ }
```

Update `src/app/(app)/budget/[tourId]/page.tsx`:
- Change the import from `'@/components/budget/BudgetTabNav'` to `'@/components/budget/budget-tab-utils'` for `resolveBudgetTab` and `BudgetTab` type only. Keep the `BudgetTabNav` component import on the same line if it's still used as a JSX child somewhere; reference doesn't cross the boundary.

## 3. Phase 2 — Suppress AdvanceSectionBuilder's internal Library when wrapped in the shell (~45 min)

**Symptom (v2 smoke test 5):** `/advance/[tour]/[show]?mode=edit` shows TWO Template Library columns. The new `AdvanceBuilderShellClient` (wrapping shell) has its own `<AdvanceSectionLibrary>` on the left. Inside the canvas, `<AdvanceSectionBuilderDynamic>` renders the OLD `AdvanceSectionBuilder` whose `SetupMode` (line ~1060) renders its OWN 2-column grid (Library + Canvas). Result: shell-Library, old-Library, old-Canvas, shell-FieldProperties — four columns, two libraries.

### 3.1 Investigation step

Read `src/components/advance/AdvanceSectionBuilder.tsx` around the `SetupMode` definition (~line 711–1060). Find:
- The signature of `SetupMode` — what props does it currently accept?
- The `<div className="grid grid-cols-1 gap-6 lg:grid-cols-2">` at the start of SetupMode's return (around line 1061). That's the 2-column grid.
- The first `<div>` inside that grid (the Library column, around lines 1063–1144). That's what we need to optionally suppress.

Also read `src/components/advance/AdvanceSectionBuilderDynamic.tsx` — confirm it just dynamic-imports `AdvanceSectionBuilder`. If yes, prop pass-through is straightforward.

### 3.2 Fix

Add a `wrappedInShell?: boolean` prop to `AdvanceSectionBuilder` (and pass-through via `AdvanceSectionBuilderDynamic`). When `true`:
- `SetupMode`'s outer grid changes from `lg:grid-cols-2` to `lg:grid-cols-1`.
- The Library column (the first `<div>` inside the grid, the `flex flex-col rounded-xl border` containing `<h3>Template Library</h3>`) is NOT rendered.
- The Canvas column (the second `<div>` inside the grid, around line ~1144 onwards) renders as before.

Then in `AdvanceBuilderShellClient.tsx` line 187:

```tsx
<AdvanceSectionBuilderDynamic
  tourId={tourId}
  routingId={routingId}
  wrappedInShell={true}
/>
```
