## 2. Phase 1 — Path-aware ArtistTourContext hydration (~45 min)

### 2.1 Reproduction case (verbatim from Adam's smoke)

User on Artist A's Budget at:
```
/budget/2bd32ef7-a886-4327-be54-cbeea7799d7a?artist_id=2ef20f57-540f-474e-8ffe-4c86656313ec
```

Clicks Advance icon in `<ProductRail>`. Lands on Artist B's Advance:
```
/advance/67d091fd-e89e-4107-938c-8c63d9a34d49?artist_id=44e28b27-f41a-44f7-b7ae-a7d45c12742c
```

Adam reports: he had never selected Artist B in this session.

### 2.2 Root cause (settled, do not re-diagnose)

`src/contexts/ArtistTourContext.tsx` lines 82-91:

```ts
useLayoutEffect(() => {
  if (typeof window === 'undefined') return;
  const lsArtist = localStorage.getItem(STORAGE_ARTIST);
  const lsTour = localStorage.getItem(STORAGE_TOUR);
  const nextArtist = urlArtistId ?? lsArtist ?? null;
  const nextTour = urlTourId ?? lsTour ?? null;       // ← BUG
  setSelectedArtistIdState((prev) => (prev === nextArtist ? prev : nextArtist));
  setSelectedTourIdState((prev) => (prev === nextTour ? prev : nextTour));
  setHydrated(true);
}, [urlArtistId, urlTourId]);
```

When the URL is `/budget/[A-tour]?artist_id=A`:
- `urlArtistId = A` (from `?artist_id=`)
- `urlTourId = null` — because the tour is a **path segment** (`/budget/[A-tour]`), not a query param
- Falls through to `lsTour` (localStorage)
- If localStorage holds a stale tour from a past session (e.g. Artist B's tour from yesterday's session), `selectedTourId` becomes B's tour
- ProductRail then builds Advance href as `/advance/${selectedTourId}` = `/advance/[B-tour]`
- Click lands on Artist B's content despite the user being on Artist A

The same bug applies to artist when on `/artists/[uuid]` paths — that path encodes the artist as a path segment too. URL query takes precedence over path; path takes precedence over localStorage.

### 2.3 Fix

Add two pure helpers (file-scope, above the provider):

```ts
/** Extract a tour UUID from /budget/[uuid], /advance/[uuid], or
 *  /operations/[uuid] paths. Returns null for any other path. */
function extractTourIdFromPath(pathname: string): string | null {
  const m = pathname.match(
    /^\/(?:budget|advance|operations)\/([^/?#]+)/,
  );
  // Skip path-segment lookups when the segment is a known
  // non-UUID landing slug. Add to this list as new dynamic
  // routes appear; the canonical cases today are tour UUIDs.
  if (!m) return null;
  const candidate = m[1];
  if (!candidate) return null;
  return candidate;
}

/** Extract an artist UUID from /artists/[uuid] paths. */
function extractArtistIdFromPath(pathname: string): string | null {
  const m = pathname.match(/^\/artists\/([^/?#]+)/);
  return m?.[1] ?? null;
}
```

Update the `useLayoutEffect` at lines 82-91 to consult path before localStorage:

```ts
useLayoutEffect(() => {
  if (typeof window === 'undefined') return;
  const lsArtist = localStorage.getItem(STORAGE_ARTIST);
  const lsTour = localStorage.getItem(STORAGE_TOUR);
  const pathArtist = pathname ? extractArtistIdFromPath(pathname) : null;
  const pathTour = pathname ? extractTourIdFromPath(pathname) : null;
  // Resolution: URL query → path segment → localStorage → null.
  // Path-segment wins over localStorage so stale stored values
  // can never override the route the user is actually on.
  const nextArtist = urlArtistId ?? pathArtist ?? lsArtist ?? null;
  const nextTour = urlTourId ?? pathTour ?? lsTour ?? null;
  setSelectedArtistIdState((prev) => (prev === nextArtist ? prev : nextArtist));
  setSelectedTourIdState((prev) => (prev === nextTour ? prev : nextTour));
  setHydrated(true);
}, [urlArtistId, urlTourId, pathname]);
```

Note the `pathname` addition to the deps array — required because path now affects the resolution.

### 2.4 Stale localStorage write hardening (also fix this in same commit)

Add a guard so localStorage doesn't drift further: when `setSelectedArtistId` is called with a new value (line 120), the existing code clears the tour (line 125). Good. But consider the inverse — if the path-aware hydration discovers a tour that matches a different artist than localStorage had, we should also flush the stale localStorage values to avoid the same desync re-occurring on the next render.

Add to the `useLayoutEffect` after the state setters:

```ts
// If the resolved values differ from localStorage, write the
// resolved values back. This prevents stale localStorage from
// re-asserting itself across navigations. Only write when there's
// a value to store (don't blow away an unset value).
if (typeof window !== 'undefined') {
  if (nextArtist && nextArtist !== lsArtist) {
    localStorage.setItem(STORAGE_ARTIST, nextArtist);
  }
  if (nextTour && nextTour !== lsTour) {
    localStorage.setItem(STORAGE_TOUR, nextTour);
  }
}
```

## 3. Phase 2 — Suppress AdvanceDateStrip when wrappedInShell (~15 min)

### 3.1 Symptom (Adam's Sprint 3 smoke)

`/advance/[tour]/[show]?mode=edit` still shows the OLD `AdvanceDateStrip` (the coloured day-type calendar column from `AdvanceSectionBuilder`) inside the canvas, alongside the shell's `AdvanceUpcomingSidebar`. Two day columns, one each from old and new code.

### 3.2 Root cause

`src/components/advance/AdvanceSectionBuilder.tsx` lines ~575-585 — the date strip is rendered as a sibling to `mainContent`, NOT inside `SetupMode`:

```tsx
return (
  <div className={...}>
    {allDates.length > 0 ? (
      <div className="flex gap-4">
        <AdvanceDateStrip ... />        // ← rendered here, sibling to mainContent
        <div className="flex-1 min-w-0 space-y-6">{mainContent}</div>
      </div>
    ) : (
      <div className="space-y-6">{mainContent}</div>
    )}
  </div>
);
```

Sprint 3 Phase 2 added a `wrappedInShell` prop and gated the Library column inside `SetupMode`. But `AdvanceDateStrip` is rendered HIGHER up in the component tree, outside SetupMode entirely. The flag never reached this render path.

### 3.3 Fix

Use the existing `wrappedInShell` prop to gate the date strip too. Update the return block at lines ~575-585:

```tsx
return (
  <div className={...}>
    {allDates.length > 0 && !wrappedInShell ? (
      <div className="flex gap-4">
        <AdvanceDateStrip ... />
        <div className="flex-1 min-w-0 space-y-6">{mainContent}</div>
      </div>
    ) : (
      <div className="space-y-6">{mainContent}</div>
    )}
  </div>
);
```

Single-condition change: add `&& !wrappedInShell` to the conditional. When wrapped, the date strip is suppressed — the shell's `AdvanceUpcomingSidebar` is the canonical day picker in builder mode.
