## P1 — Money is wrong or about to be

### 1. FX: three non-communicating mechanisms → the P&L bottom line is arithmetically incoherent (VERIFIED)

- `src/lib/budget/fx.ts:1-21` — hardcoded static GBP-pivot table (USD 0.79, EUR 0.85…), comment says "v1… admin overrides later" (never built). Used by 10+ consumers including `computeBudgetPnl.ts:163-164` for **expense** conversion, plus BudgetMainTable/SummaryTab/SpreadsheetView/BurnBar/GridView and PDF/XLSX export.
- `src/lib/budget/fxRates.ts:13-30` — `budget_fx_rates` table, admin-editable live rate.
- `src/app/api/budget/exchange-rate/route.ts:13-65` — fetches a real live rate, persists to a **third** store (`budget_settings.exchange_rate`).
- Migration 225 — `budget_income.locked_fx_rate`, write-once at settlement (income side).

Net effect: income converts via locked/live rates, expenses via a stale hardcoded table. Every multi-currency tour's net figure is silently wrong today. **Spec: `CC_FX_UNIFY.md`** (one design decision needed first — see §Decisions).

## P2 — Structural integrity

Legacy `venues` table (near-dead) · `canonical_venues` (214/226, service-role writer only, no edit UI) · `routing.venue_*` text columns (captured at pick-time, never resynced) · `advance_instances.data` JSONB (frozen snapshot, `advance/[routingId]/route.ts:433-438`).
