# UX walk — 2026-07-03 (Vercel deploy of feat/data-integrity-pass, desktop 1372px)

Flows walked: workspace dashboard → artist home → tour select → Operations summary → Routing grid → Budget grid → Advance list. Every finding was observed on screen; screenshots referenced by page.

## A. Bugs found by looking (mechanical fixes → CC_MASTER_PASS STAGE 6)

1. **Off-by-one dates in Operations summary "Upcoming Shows"** (HIGH). Summary lists EXIT/IN Sep 8, Union Stage Sep 10, Middle East Sep 11, Gramercy Sep 12, Adelaide Hall Sep 14. Routing grid (source of truth) and Advance list both say Sep 9, 11, 12, 13, 15. Every row renders one day early — classic `new Date('YYYY-MM-DD')` UTC-shift in the summary widget only (routing + advance render correctly, so the fix is localized). Find the date formatting in the ops summary upcoming-shows component; parse as local date (or reuse whatever routing/advance use).
2. **"Next show" doesn't filter day types** (HIGH). Workspace artist card: "NEXT: 5 SEP · NASHVILLE" — Sep 5 is a *Day Off* row. Ops summary says "next Sep 8" — a *Rehearsal*. First actual Show Day is Sep 9. "Next" pickers are taking the first routing row ≥ today instead of the first `day = Show Day`. Fix everywhere the "next" chip renders (workspace card, artist card, ops SHOWS stat).
3. **Show-count terminology split** (MED). Advance header: "24 SHOWS · SEP 5 → SEP 28"; filter bar on the same page: "11 shows". 24 = routing rows, 11 = show days. Never call routing rows "shows". Header should read "11 shows · 24 days" (or similar).
4. **Activity feed ACTOR column renders "—" at workspace + artist tiers** (MED) while the Operations feed shows "Adam 'mr Big' Rowley" — the data exists; the workspace/artist feed components don't render it. Either wire the actor through or drop the column (an all-dash column looks broken).
5. **Stale copy references retired chrome** (MED): artist home "Pick a tour" panel says "…the left rail unlocks once you do." The left rail was retired for the two-bar nav. Rewrite: "…Choose one to unlock Operations, Budget and Advance in the bar above."
6. **"Active" means two things on one screen** (MED): banner "ACTIVE TOUR: USA Headline '26" sits directly above stat card "ACTIVE TOURS: 0". Banner = selected; stat = in-progress-today. Rename the stat "ON TOUR NOW" (or show "3 in planning" when zero) and/or the banner "CURRENT TOUR".
7. **Currency symbol whiplash across tiers** (MED, ties into FX stage 2): workspace header "£175K COMMITTED"; artist page "BUDGET COMMITTED $16K"; budget page "US$2,495". Even if the amounts differ legitimately by scope, mixed symbols with no scope label reads as broken. Aggregate stats must state their display currency and scope ("committed across 3 tours · GBP").

## B. Flow/design recommendations (need Adam's eye — NOT for CC without discussion)

8. **First-paint blank screen ~3s** on the workspace dashboard (black page, chrome only, no skeleton). Add skeleton cards for stats/artist cards/activity. Applies to artist home too.
9. **Product cards (Operations/Budget/Advance) on artist home are ~200px tall and ~85% empty.** They repeat static descriptions ("Routing, channel list, rooming…") whether or not a tour is selected. Once a tour is active, fill them with live state: Operations → next show + pending tasks; Budget → remaining/committed; Advance → x/11 not started. Empty cards read as unfinished product.
10. **The 30-day calendar strip renders "0 dates" for a tour starting in 5 weeks** — a large empty component whose honest content is one sentence. Replace empty state with "Next show Sep 9 · EXIT/IN Nashville → jump to routing" or auto-shift the window to the tour's first week.
11. **Classic | Grid toggle in Budget** ships two parallel renderings of the same data. This is the "multiple ways of doing things" pattern you're trying to kill. Pick Grid; keep Classic behind a query param for one release, then delete.
12. **8 auto-generated "Unassigned Hotel — SGL" rows in Accommodation** — indistinguishable noise. Label with city/date ("Nashville · Sep 5-8 · SGL") and collapse identical unassigned rows into one line with a count until rooms are assigned.
13. **Routing grid save model is ambiguous**: a prominent "Save routing" button coexists with the new debounced autosave. If autosave is on, the button should become a SaveStatus pill (per the repo's own useAutoSave convention); a big explicit Save next to autosave makes users distrust both.
14. **Good bones worth keeping/extending**: two-bar nav reads clearly; Operations summary stat cards with deep-links (Routing→ / Personnel→) are exactly the right pattern — replicate on artist home (finding 9); drive-time chips between routing rows are excellent; budget keyboard-hints footer is excellent; Advance status filter chips are the right onboarding-free pattern.

## C. Tutorial/onboarding (deferred — needs a session of its own)
The "Pick a tour to get started" panel is the only onboarding in the walked flows. Empty states are the cheapest tutorial surface: every list page should say what the thing is + one primary action (the Advance and Routing pages already have real data so their empty states weren't seen this walk). A proper first-run checklist (create artist → create tour → add routing → assign crew → open advance) belongs on the artist home in place of the empty calendar strip. Spec after the master pass lands.
